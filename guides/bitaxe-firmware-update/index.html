Firmware update guide

How to Update Bitaxe and NerdAxe Firmware

To update a supported Bitaxe or NerdAxe through the web flasher, connect it by USB, select its exact hardware and a compatible release, decide whether to preserve settings, and install. After the reset sequence, confirm the miner boots and reconnects before treating the update as successful.

Quick overview

  • Use the correct firmware family: select Bitaxe for supported AxeOS hardware or NerdAxe for supported Nerd*OS models. Match the model and board, not just the ASIC chip.
  • USB is required for this method: use a supported desktop Chrome, Edge, or Brave browser, a data-capable USB cable, and the miner’s appropriate power supply.
  • Verified releases chooses the file: the flasher downloads a matching factory image and checks its size and SHA-256 digest. Latest Releases is the normal choice; prereleases are for deliberate testing.
  • Preservation is optional: the switch is off by default. When enabled for a supported verified image, it skips the settings partition, but it is not a backup or a compatibility guarantee.
  • Check the miner after flashing: completion confirms the write and reset sequence. Separately verify boot, network access, the installed version, cooling, and accepted mining work.

What do you need before updating?

You need the exact supported miner, a desktop browser with Web Serial, a working USB data cable, and stable power appropriate to the board. Record your existing network and mining configuration before changing firmware.

A firmware update replaces software on the controller; it does not change the physical board or make an image for another model compatible. A matching ASIC name by itself is not enough to identify the right target.

  • Browser: use a current desktop version of Chrome, Edge, or Brave. Safari, Firefox, phones, and tablets cannot perform this flasher’s USB installation.
  • Cable and power: use the board’s USB programming port and maintain its required power and cooling. USB power alone is not a substitute for the correct mining power supply.
  • Configuration: privately record the Wi-Fi details, mining-service address, worker or receiving-address configuration, and any settings you will need to restore. Never share a seed phrase or private key.
  • Release notes: check supported hardware, known issues, and configuration changes for the intended release. Do not update solely because a version number is higher.
Step 1

Identify the model, board, and installed version

Match the model and board revision printed on the miner, then use its current System page as an additional reference. Record the installed firmware version so you can compare it after the update.

In AxeOS, open System to find Device Model, Board Version, and Firmware Version. In the Nerd*OS example, System lists the model and version; the flasher matches the board from the exact selected NerdAxe model.

Screen firmware is separate. Bitaxe Turbo Touch (Screen Only) updates the display controller. It does not update the Bitaxe GT miner inside the unit; each controller must be connected and selected separately.
Step 2

Connect the miner and approve its USB device

Open Verified releases, connect the miner’s programming USB port to your computer, and select Connect. In the browser’s serial-device chooser, approve only the device you intend to update.

Only one application should control that serial port at a time. Close any serial monitor or other flasher that is holding it, and keep the miner’s normal cooling and required electrical power connected.

The later controls are intentionally unavailable before the required earlier step is complete. Selecting a USB port authorizes a connection; it does not prove that the firmware family or model has been chosen correctly.

Step 3

Choose the family, model, board, and release

Select the correct firmware family and exact hardware, then choose a compatible version from Latest Releases. Verified releases retrieves the matched factory image automatically, so you do not need to choose a local file for this method.

  1. Miner family: choose Bitaxe for supported Bitaxe/AxeOS devices or NerdAxe for supported Nerd*OS models.
  2. Release channel: choose Latest Releases for a normal stable update. A prerelease is offered only when an eligible newer prerelease is available; use it only when you intend to test that release.
  3. Model: select the exact model, including variants such as Gamma, Gamma Duo, Gamma Turbo, GammaHex, Naja Duo, or NerdQAxe++.
  4. Board match: choose the printed Bitaxe board revision. For supported NerdAxe models, review the automatically matched board.
  5. Firmware version: choose a listed release that supports the selected hardware, after reading its release notes.

The list may contain the newest stable release and up to five earlier stable versions. A release appears only when it contains a factory image for that hardware, so a new board cannot be rolled back to a version released before its support existed.

The flasher verifies the downloaded file against its expected size and SHA-256 digest before writing. Those checks establish that the file matches the listed release, not that every firmware release is defect-free or safe for every configuration.

Step 4

Should you preserve miner settings?

Enable Preserve miner settings only when you intend to retain a supported verified image’s settings partition and the release notes do not require a reset. It is off by default, and leaving it off writes the settings data contained in the selected factory image.

When preservation is enabled, the flasher skips the designated NVS settings partition. It does not read, export, or upload the saved Wi-Fi, pool, or other configuration values. Old settings may still be incompatible with a new release, which is why keeping a separate private record matters.

Advanced is a different workflow. It accepts a local merged ESP32-S3 image and writes without preserving settings. Do not switch to Advanced merely because a model or older version is absent from the verified catalog.

Step 5

Install the verified firmware and let the reset finish

Review the selected hardware, release, and preservation choice, then select Start Flashing. Keep USB, required power, and cooling connected while the write, verification, and reset sequence runs.

Follow any hardware-specific bootloader instructions displayed by the flasher. Do not open a second flashing session or repeatedly disconnect the cable while a write is in progress. If the flasher reports a mismatch or verification failure, stop and resolve it rather than bypassing the check.

After verifying the write, the flasher sends a reset signal and releases its serial connection. The completion screen reports that local sequence, not a successful application boot or a connection to your mining service.

Step 6

Confirm the update worked on the miner

Confirm that the device boots and that its System page reports the intended firmware version. Then check its network connection, mining configuration, cooling, and accepted work at the selected mining service.

  • Boot and version: check the display and reopen the local dashboard. Compare the installed version with the release you selected.
  • Network and configuration: confirm the miner reconnects to the intended network and uses your intended mining-service and payout or worker details. Restore your recorded configuration if needed.
  • Cooling and operation: verify that fans operate, temperatures are appropriate for the hardware, and hashrate updates normally after startup. This walkthrough does not prescribe tuning values.
  • Accepted work: check both the device’s share counters and the mining service’s own records. A fan, a nonzero hashrate, or a dashboard connection alone does not establish that accepted work is reaching the intended service.

If the miner no longer appears at its previous address, check your router’s connected-device list or the device display. A changed network configuration or address is different from a failed firmware write.

What if the update does not start or the miner will not boot?

Start with the reported error and the exact board’s recovery instructions. Recheck the cable, browser, port access, selected hardware, and image source before attempting another installation.

SymptomWhat to check
No USB device appearsTry a known data-capable cable and the correct programming port. Use a supported desktop browser. Check the board’s USB driver and operating-system permissions if required.
Port is busy or access is deniedClose other serial monitors, firmware tools, and browser tabs using that device. Reconnect the cable, then reopen the chooser.
Bootloader connection failsFor a supported Bitaxe or NerdAxe that has the documented buttons, hold BOOT, press and release RESET while continuing to hold BOOT, then release BOOT and retry. Follow your exact hardware’s instructions where they differ.
Wrong chip or verification errorStop. Recheck the selected model, board, and compatible image. Do not disable the integrity or compatibility checks.
Write finishes, but no normal bootAllow the reset sequence to finish, then check the display and required power. Review the release’s recovery procedure. If settings compatibility is the issue, a documented clean installation may be needed and will require restoring configuration.

Repeated failures deserve diagnosis, not repeated guesses with different firmware. Keep the error text and selected release available when asking for help, but remove passwords, seed phrases, private keys, and other sensitive information from any report.

Frequently asked questions

Can I update my miner over Wi-Fi instead?

Some AxeOS and Nerd*OS releases offer updates through the miner’s own web interface. This guide covers the separate USB web flasher, which requires a data-capable USB connection. Use the update method and image type documented for your hardware; a browser-flasher factory image is not interchangeable with every web-update file.

Will flashing keep my Wi-Fi and pool settings?

Settings preservation is optional and off by default. For a supported verified ESP image, enabling it skips the designated settings partition. It is not a backup or a guarantee that older settings will work with the new firmware. Record your configuration before updating.

Do I need to download a firmware file first?

No. Verified releases downloads the factory image matched to your selected family, model, board, and version. Advanced is for a local merged ESP32-S3 image and does not preserve settings; it is not the normal route for this walkthrough.

Why does my miner not appear in the USB chooser?

A charge-only cable, unsupported browser, missing USB driver or permission, or another program holding the serial port can prevent access. Use a supported desktop browser, a known data cable, and the correct USB port. If needed, follow the board’s documented bootloader procedure.

Does a completed flash mean the miner is mining?

No. Completion reports the local write, verification, and reset sequence. Confirm that the miner boots, reconnects to your network, runs the intended firmware, and submits accepted work to the intended mining service. A fan spinning or a hashrate number alone does not confirm all of those checks.

Can I install an older firmware version?

The flasher offers up to five earlier stable releases only when they contain a factory image for the selected hardware. A version released before support for your board is not offered. Check the release notes and configuration compatibility before a downgrade.

Release notes and source information

Check the upstream notes for the exact version and model you plan to install. The flasher’s catalog determines which verified factory images it can offer.
